# AD Me 콘텐츠·계정 사고 대응 초안

적용 범위는 무료 성인 베타와 격리된 TEST 시연이다. 운영 담당이 접수 및 사용자 안내를 맡고, 개발 담당이 영향 범위와 복구를 확인한다. 운영 승인과 개인정보 통지 절차는 U001에서 확정한다.

## 접수와 대응

1. 프로필의 자료 정정·이슈 신고 또는 개인정보 처리방침에 게시된 지원 메일로 접수한다. 요청자에게 문의 번호를 전달하고 유형, 대상 링크, 발생 시각을 기록한다.
2. 운영 담당이 공개 여부, 관련 계정, 지속 여부를 확인한다. 사용자 비밀번호, 복구 링크, 세션 토큰을 요청하지 않는다. 재현은 격리된 환경이나 최소 권한 계정에서 진행한다.
3. 실제 피해가 계속될 수 있으면 MFA가 확인된 관리자가 D059 운영 화면에서 사유를 기록해 관련 프로필·캠페인을 잠근다. 단순 소유자 비공개와 달리 운영 잠금은 소유자의 재공개·삭제 후 재생성으로 해제되지 않는다. 계정 탈취 의심 시 USER 콘솔 담당이 인증 접근 제한과 세션 철회를 실행한다. JWT는 만료 전까지 유효할 수 있으므로 기존 토큰의 DB·RPC·파일 접근 거부를 별도로 확인한다.
4. 권한이 있는 담당자만 사고 기록에 접근한다. 증빙은 대상 ID, 판단 근거가 되는 최소 정보, 시작·종료 시각, 변경 전후 상태와 검토자만 남긴다. 신고 원문·이메일·개인정보는 공개 Git에 첨부하지 않는다.
5. 운영 책임자가 실제 영향과 당시 규정을 확인해 사용자 통지·기관 신고의 적용 여부와 결정을 기록한다. 의심만으로 당사자 신원을 공개하거나 책임을 확정하지 않는다.
6. 피해 원인이 제거되었는지, 접근 차단·철회가 지속되는지, 사용자 상태가 복구됐는지 검증한다. 복구 근거와 재발 방지 대응을 기록한 뒤 종료한다.

| 유형 | 즉시 확인 | 제한·복구 확인 |
|---|---|---|
| 사칭 | 실제 계정 소유 근거, 신고 채널, 공개 링크 | 의심 프로필 비공개 → D026 소유 확인·이의 신청 검토 → 재공개는 근거 승인 후 |
| 개인정보 노출 | 공개 위치와 범위, 재수집 경로, 최소 증빙 | 원본 공개 중단 및 캐시·첨부·파생 노출 확인 → 권리 요청·통지 검토 |
| 명예훼손 우려 | 게시된 주장·출처·당사자 입장을 분리 | 검토 전 공개 보류 → 확인된 자료와 정정 검토 → 근거 없는 자동 점수 반영 금지 |
| 서비스 침해 | 영향 계정·서비스·기간, 운영 로그 접근권 | 관련 동작 차단과 자격 증명 교체를 콘솔 담당에 요청 → 권한·백업·재발 방지 검증 |
| 계정 탈취 | 소유자 본인 확인과 작업 이력 | 접근 제한, 재인증·세션 철회 → 소유자가 통제하는 메일에서 복구 → 권한 변경 감사 |

## 종료 기록

기록 항목은 사건 ID, 접수 시각(KST), 유형, 확인 범위, 제한 및 복구 증빙, 통지 검토 결과, 보존 범위, 종료 승인자, 후속 티켓이다. 개인정보 보존 기간과 접근 권한 목록은 U001의 최종 정책 결정에 따라 확정한다.

[개인정보보호위원회](https://www.pipc.go.kr/) · [개인정보 포털](https://www.privacy.go.kr/)

## 담당과 사용 경로

접수/영향 판단/외부 통지 결정은 운영자 우성현, 지원·권리 요청은 서비스에 공개된 2242798@donga.ac.kr로 접수한다. 개발 담당은 재현·영향 경로·로컬 수정/회귀·복구안을 준비한다. 콘솔 접근 제한/키 교체/배포·롤백은 USER만 수행한다. 독립 검토자가 공개 복구 근거를 확인한다. 역할을 연락 불가 개인의 이름이나 임의 24시간 SLA로 대체하지 않는다.

운영 잠금 경로는 `/admin` → 해당 creator/campaign 상태와 사유 입력이며 서버는 `/api/admin/moderate` → `moderate_entity`에서 MFA·승인·역할을 검증한다. 위임 content/support는 classic admin 권한과 같지 않다. 근거/당사자 입장은 `/admin/reviews`, 정정 제출은 해당 이력 제출 경로에서 버전과 공개 동의를 확인한다. 사용자 신고·대화 차단은 당사자 화면을 이용한다. 운영자는 타인 세션으로 로그인하거나 사용자 비밀번호/코드를 대신 입력하지 않는다.

## 다섯 가상 사고의 모의훈련 카드

|구분|접수·탐지|초기 제한과 비공개 증빙|복구·종료 기준|
|---|---|---|---|
|사칭|본인 주장과 공개 URL을 분리하고 소유 증명을 요청|의심 프로필 운영 잠금, 익명 DTO/상세/제안 후보에서 제외, 타인 관리자 거부 확인|D026 소유 근거·이의 검토 후 승인자가 해제. 주장만으로 소유권 이전 금지|
|개인정보 노출|최소 대상 링크/시각을 접수, 원문 전체를 Git·공유 캡처에 복사하지 않음|프로필/브랜드 공개 철회와 이미지 접근 거부 확인. 원본·캐시·정규화 공개 DTO 경로 조사|삭제/보존 예외·백업 재적용은 D014/D079 계약으로 추적. 공개 철회를 전체 파기로 종료하지 않음|
|명예훼손 우려|주장·출처·당사자 입장을 개별 버전으로 분리|D057 검토 원문은 비공개, 확정 전 위험 점수/공개 문구 반영 금지|승인된 최신 근거/공개 동의·정정 이력 확인 후 복구. 실제 법률 판단·유무죄 단정 금지|
|서비스 침해|최소 로그·영향 자원·기간·권한을 확인|USER가 관련 기능/계정을 제한하고 자격 증명 교체 필요성을 판단. 개발자는 같은 조건의 로컬 권한 부정 테스트 수행|원인 수정·세션/파일/직접 REST 재검증, USER 복구/배포 결정, 사후 확인|
|계정 탈취|검증된 메일 통제와 변경 이력 확인. 인증 코드/복구 링크 수집 금지|USER가 접근 제한·세션 철회, 실제 남은 JWT 경로 확인. 복구 링크는 GET만으로 소비하지 않음|소유자가 자기 메일로 재인증, 관리자 MFA·권한 재검토, 변경 이력·지원 판단 검토 후 종료|

각 훈련은 가상 사건임을 표시하고 사건 ID/역할/사용한 가상 자원/접수→제한→근거→통지 검토→복구→재발 방지의 결과를 기록한다. 실제 당사자에게 메일을 보내거나 콘솔 조치·유출 신고를 수행한 것으로 보고하지 않는다. 연락처·최종 정책·실제 담당자 참여 훈련이 남으면 U001/D064 외부 gate를 유지한다.

법령 검토 근거는 [개인정보 보호법 제30조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1006185717)와 [제21조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1029334977)다. 보존 예외의 항목·근거·기한은 별도 승인하며 임의 기간을 법적 의무로 확정하지 않는다. 세션 한계는 [Supabase 사용자 관리 문서](https://supabase.com/docs/guides/auth/managing-user-data)와 함께 확인한다. 실제 통지/신고 적용 여부는 사고 시점의 규정과 사실관계로 재검토한다.
