# AD Me 콘텐츠·계정 사고 대응 초안

적용 범위는 무료 성인 베타와 격리된 TEST 시연이다. 운영 담당이 접수 및 사용자 안내를 맡고, 개발 담당이 영향 범위와 복구를 확인한다. 운영 승인과 개인정보 통지 절차는 U001에서 확정한다.

## 접수와 대응

1. 프로필의 자료 정정·이슈 신고 또는 개인정보 처리방침에 게시된 지원 메일로 접수한다. 요청자에게 문의 번호를 전달하고 유형, 대상 링크, 발생 시각을 기록한다.
2. 운영 담당이 공개 여부, 관련 계정, 지속 여부를 확인한다. 사용자 비밀번호, 복구 링크, 세션 토큰을 요청하지 않는다. 재현은 격리된 환경이나 최소 권한 계정에서 진행한다.
3. 실제 피해가 계속될 수 있으면 관련 프로필·자료의 공개를 중단하고, 계정 탈취 의심 시 운영 담당이 인증 콘솔에서 계정 접근 제한과 세션 철회 여부를 확인한다. D059 영구 운영 잠금이 준비되기 전에는 임시 비공개 이후 소유자에 의한 재공개 여부를 확인한다.
4. 권한이 있는 담당자만 사고 기록에 접근한다. 증빙은 대상 ID, 판단 근거가 되는 최소 정보, 시작·종료 시각, 변경 전후 상태와 검토자만 남긴다. 신고 원문·이메일·개인정보는 공개 Git에 첨부하지 않는다.
5. 운영 책임자가 실제 영향과 당시 규정을 확인해 사용자 통지·기관 신고의 적용 여부와 결정을 기록한다. 의심만으로 당사자 신원을 공개하거나 책임을 확정하지 않는다.
6. 피해 원인이 제거되었는지, 접근 차단·철회가 지속되는지, 사용자 상태가 복구됐는지 검증한다. 복구 근거와 재발 방지 대응을 기록한 뒤 종료한다.

| 유형 | 즉시 확인 | 제한·복구 확인 |
|---|---|---|
| 사칭 | 실제 계정 소유 근거, 신고 채널, 공개 링크 | 의심 프로필 비공개 → D026 소유 확인·이의 신청 검토 → 재공개는 근거 승인 후 |
| 개인정보 노출 | 공개 위치와 범위, 재수집 경로, 최소 증빙 | 원본 공개 중단 및 캐시·첨부·파생 노출 확인 → 권리 요청·통지 검토 |
| 명예훼손 우려 | 게시된 주장·출처·당사자 입장을 분리 | 검토 전 공개 보류 → 확인된 자료와 정정 검토 → 근거 없는 자동 점수 반영 금지 |
| 서비스 침해 | 영향 계정·서비스·기간, 운영 로그 접근권 | 관련 동작 차단과 자격 증명 교체를 콘솔 담당에 요청 → 권한·백업·재발 방지 검증 |
| 계정 탈취 | 소유자 본인 확인과 작업 이력 | 접근 제한, 재인증·세션 철회 → 소유자가 통제하는 메일에서 복구 → 권한 변경 감사 |

## 종료 기록

기록 항목은 사건 ID, 접수 시각(KST), 유형, 확인 범위, 제한 및 복구 증빙, 통지 검토 결과, 보존 범위, 종료 승인자, 후속 티켓이다. 개인정보 보존 기간과 접근 권한 목록은 U001의 최종 정책 결정에 따라 확정한다.
