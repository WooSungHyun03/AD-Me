# AD Me 화면 감사

## 확인 범위

Next.js의 `page.tsx`를 자동 순회하고 공개 페이지와 QA 워크스페이스의 실제 링크에서 동적 주소를 추가했다. Chromium으로 렌더링하고 화면 너비, 버튼 위치, 브라우저 오류를 기록했다. 핵심 화면의 8개 뷰포트는 360×800, 390×844, 430×932, 768×1024, 1024×768, 1280×800, 1440×900, 1920×1080이다. 나머지 화면은 390×844와 1440×900에서 봤다. 역할별 화면 캡처와 원본 Lighthouse 기록은 Git에서 제외된 `output/playwright/premium/`에 보관했다. 결제 인증 제출, 비밀번호 변경, 공고 게시, 실제 외부 발송은 시각 감사에서 실행하지 않았다.

## 운영 검증 결과

- 디자인 검토에 design-taste-frontend 스킬을 적용했다. 설치된 Playwright, axe-core와 Lighthouse를 사용했다. 참고 사이트는 실제 Chromium에서 스크롤 가능한 페이지로 열어 데스크톱·모바일 캡처를 보관했다.
- 최종 운영 브라우저에서 서로 다른 경로 60개, 역할 조합 62개, 뷰포트 관측 190회를 기록했다. 페이지 가로 넘침과 브라우저 JavaScript 예외는 0건이었다. 별도 관리자 메뉴, 가입 메일 재전송과 저장 검색 등을 포함한 5개 경로는 404였다. `/explore`의 최초 모바일 캡처는 인증 이동 중 실행 문맥이 바뀌었다. 브랜드로 로그인한 재검사에서 8개 폭 모두 200을 확인했다. 크리에이터 계정의 광고 이력 입력 경로는 재검사에서도 404였다.
- 광고 공고 게시권 CTA의 운영 명암비는 약 16.27:1, 높이는 48px였다. 360·390·1440·1920px에서 중앙 클릭 위치를 확인했다. 무료 베타에서는 초안 작성으로 연결하고, 격리 TEST 환경에서는 TEST 결제 버튼과 로그인 보호를 확인했다. 실제 Toss 승인은 이번 검증에서 수행하지 않았다.
- 최종 운영 E2E 20건, 격리 TEST CTA 2건과 AI 워커 API 2건, main 단위 420건, 운영 호환 빌드 단위 167건 및 타입·린트·빌드를 완료했다. 스튜디오 공개 경로 제거 뒤에도 격리 환경에서 AI 작업 접수와 결과 조회가 동작했다.
- axe-core WCAG A·AA 규칙 본 검사 22회와 추가 검사 2회에서 위반을 발견하지 않았다. 자동 규칙 결과는 전체 WCAG 적합성을 뜻하지 않는다. Lighthouse 모바일 랩 단일 관측에서 홈·요금제·탐색의 성능과 접근성 점수는 각각 100점이었다. 홈 LCP는 개편 전 3.02초에서 0.92초, 요금제는 0.93초, 최종 탐색은 0.92초였다. CLS는 모두 0.003 이하이며 현장 INP는 미측정이다.
- 최종 Vercel 배포는 `dpl_G3S8oSBWEEadE4dShsgjKHjKa854`, 운영 호환 소스는 `11af311f50e3ff8280ce530879031d636af908ca`다. `www.be-celeb.org`는 apex로 308 이동하며 홈·탐색·요금제는 운영 도메인을 canonical로 표시한다. 운영 DB 스키마와 호환 빌드 정책 때문에 GitHub main 구현 커밋과 운영 소스 커밋은 별개다.

브라우저 캡처는 `output/playwright/premium/before/`와 `output/playwright/premium/final/`, 홈·요금제·탐색의 데스크톱·모바일 시각 차이는 `output/playwright/premium/diff/`에 있다. 요약 검증은 `harness/evidence/VISUAL-REDESIGN-20261123/verification.json`에 보관했다.
