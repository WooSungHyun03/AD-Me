# AD Me DEV-B 바이브코딩 실행 티켓

이 문서의 45개 티켓, 총 219SP만 담당한다. 역할별 분업이 아니며 다른 담당도 UI·서버·DB를 모두 수정한다. 전체 88개 중 자기 담당을 넘어서 임의 재배분하지 않는다.

## 시작 프롬프트 — 코딩 에이전트에 그대로 전달

```text
너는 AD Me 프로젝트의 DEV-B 구현 담당이다. 이 문서와 같은 폴더의 SHARED_EXECUTION_CONTRACT.md를 모두 읽고 작업하라.
저장소의 기존 코드를 이어서 구현한다. AGENTS.md, 현재 git 상태, harness/service_backlog_v2.json, 세션 로그를 확인하라.
사용자는 외부 계정·콘솔·배포·API 키 발급/등록을 직접 한다. 너는 로컬 코드·마이그레이션·자동 테스트·브라우저 검증·사용자 적용 패키지를 완성하라.
준비된 자기 담당 P0부터 실행하며 선행 티켓이 미완료면 독립 가능한 코드/계약 테스트를 진행하라. 키가 없다고 모든 작업을 중단하지 마라.
가상 데이터를 실제 인플루언서로 위장하거나 mock 통과를 실제 공급자 검증으로 보고하지 마라.
티켓별 변경과 증빙을 저장하고 모든 수용 기준 통과 전 DONE으로 표시하지 마라. 사용자에게 터미널/코드 수정 작업을 떠넘기지 마라.
```

## D001 — 무료 실서비스·TEST 시연 모드 분리

- 담당/공수/단계: DEV-B · 3SP · P0 · 보강 · OPEN
- 선행 인계: 없음. 현재 기준선과 공통 계약 확인.
- 후속 인계: D002(DEV-A), D005(DEV-B), D065(DEV-A)

**읽고 수정할 위치**

- `src/lib/data.ts`
- `src/lib/billing.ts`
- `src/app/pricing/page.tsx`

**구현 지시**

serviceMode=free_beta/test_demo는 서버 값으로 판정한다. free_beta의 fixture fallback·구매 API·유료 권한 부여를 차단한다. 공개 빌드 플래그만으로 보호하지 않는다.

**완료 조건**

실서비스는 무료 기능만 노출하고 TEST 상품·시연 데이터는 별도 환경으로 격리한다.

**반드시 지킬 경계·부정 시나리오**

동일 사용자로 환경을 바꿔도 TEST entitlement가 무료 실서비스 권한/노출을 변경하지 않아야 한다.

**실행 및 테스트**

환경별 라우트·상품·데이터 노출 테스트

관련 단위/통합 테스트를 먼저 실행하고 UI 변경은 데스크톱·모바일 브라우저로 확인한다. RLS/DB 변경은 직접 REST 권한 거부와 격리 DB 적용을 확인한다. 최종 인계 시 공통 lint/typecheck/test/build 및 영향받는 E2E를 실행한다. 외부 검증이 필요한 경우 해당 U 티켓과 실제 결과를 별도로 기록한다.

**제출 산출물**

구현 파일·필요한 SQL/설정명 목록·검증 결과·비밀값 없는 `harness/evidence/D001/` 기록·상대 담당 인터페이스 변경 요약. 구현이 없으면 완료로 표시하지 않는다.
