# AD Me — 제품 요구사항(PRD): YouTube 전용

## 1. 포지셔닝과 용어
- **브랜드/광고주(Brand)**: 상품·캠페인을 등록하고 검색권을 구매해 적합한 YouTube 채널을 찾거나 공고를 게시한다.
- **유튜버/크리에이터(Creator)**: 본인의 YouTube 채널 소유권을 확인하고 상세 프로필·업무 연락처를 관리하며 공고 지원권과 상단 스폰서 회원권을 구매한다.
- **채널 디렉터리(Channel Listing)**: YouTube 공개 데이터로 발견한 실제 채널. 플랫폼 가입자·계약 가능자와 **다르다**. 가입/소유 인증 전에는 '자동 발견 채널'로 표시한다.
- **AI 검색(Search Run)**: 특정 브랜드 캠페인+필터에 대해 산출된 일회성 추천 세션. 초안 작성·기존 결과 재열람 무료. 새로운 유료 실행마다 검색권 한 개 필요.
- **광고 공고(Job Post)**: 브랜드가 유튜버 지원을 모집하는 게시물.
- **지원(Application)**: 채널 소유자가 광고 공고에 본인 프로필을 제출하는 행위.
- **스폰서(Featured Placement)**: 유료 노출 상품. 자연 추천 순위와 구분해서 상단에 별도 표시.

## 2. 비즈니스 규칙 — 사용자 의도 그대로 구현
| 행위 | 지불 주체 | 단위/상품 | 구매 흐름 | 차감/혜택 확정 시점 | 무료 재시도 |
|---|---|---|---|---|---|
| AI로 광고 적합 유튜버 찾기 | 브랜드 | SEARCH_RUN 1회/크레딧 | Toss TEST 또는 보유 크레딧 | 추천 결과 스냅샷 정상 저장 후 원자적 차감 | 동일 params_hash 재열람 무료 |
| 광고 공고 등록 | 브랜드 | JOB_POST 1회 | Toss TEST 또는 보유 게시권 | 공고가 `published`로 DB 확정될 때 | 저장 초안/검증 실패 무료 |
| 공고에 프로필 지원 | 크리에이터 | APPLICATION 1회 | Toss TEST 또는 보유 지원권 | 지원 레코드가 `submitted`로 DB 확정될 때 | 동일 유저/공고 중복 지원 금지 및 재열람 무료 |
| 상단 노출 | 크리에이터 | SPONSORED_30D | Toss TEST | 결제 최종 승인 후 30일 노출 권한 생성 | 관리자 규칙에 따라 중복 갱신/연장 |

**가격 가설 (관리자 변경 가능, TEST 값이며 실제 수익 아님)**: 검색 3,000원/회, 공고 5,000원/건, 지원 1,000원/건, 30일 스폰서 9,900원. 한 번 결제할 때 원화 가격은 서버가 상품 버전별로 확정한다. 사용자는 명세만으로 실제 금액을 받지 않는다. 이 가설은 시장 검증 결과가 아니다.

**유료 지원의 리스크**: 유튜버의 공고 참여를 위축시킬 수 있음. 사업 검증용 관리자 설정으로 무료 지원권 지급, 신규 회원 1회 체험, 쿠폰, 월 이용권 번들을 지원하되 유료 지원 기능은 구현한다. 지원 거절은 원칙적으로 자동 환불 사유가 아니고, 공고 삭제/이용불가/오류 등 서비스 미제공 상황에서만 명시한 환불 규칙에 따른다.

## 3. 역할·사용자 스토리
### 비회원
- 홈, 가격, 광고 공고 개요, 공개 채널 소개 및 개인정보/약관 확인.
- 비회원은 연락처·채팅·유료 분석에 접근 못함; 공개 채널은 자신의 가입 여부가 표시됨.

### 브랜드
- 사업체 표시명·사업 분야·담당자·선호 광고 플랫폼(YouTube만)·브랜드 설명 등록.
- 상품명/설명/카테고리/예산·기간·광고 형태(숏폼/영상 PPL/리뷰/라이브 등)/AI 검색조건 저장.
- 검색 필터: 구독자 최소·최대, 최근 업로드, 최근 N개/기간별 평균 조회수(권한 충족 시), 콘텐츠 태그, 카테고리, 지역/언어(확인된 경우만), 희망 광고 단가(본인 제공), 최근 활동, 검증 여부, 협업 가능 여부.
- AI 자연어 검색, 세부 필터/제외 키워드, 결과 카드, 근거/데이터 최신성, 후보 비교, 컬렉션, 제안 메모, 후보 추가.
- 검색 미리보기는 가격·조건·필터 유효성만 보여주고 유료 결과 전체를 노출하지 않음.
- 공고 초안 → 미리보기 → 유료 게이트 → 공개 → 관리, 마감/중단/재게시(정책 적용).
- 지원자 정렬/서류 확인, 프로필 비교, shortlist, accept/reject/hold, 인터뷰·채팅, 상태 이력.
- 직접 채널 연락 요청은 가입+채널 인증+연락 공개 동의 여부 확인. 대화는 플랫폼 내 안전하게 시작 가능하도록 한다.
- 검색·공고 구매 내역, 크레딧 잔액, 갱신/취소, 영수증(테스트임 표시), 결제 오류 처리.

### 인증된 크리에이터
- 계정 생성 후 YouTube OAuth를 통한 채널 소유 확인. 자동 발견 데이터와 owner_claim 연결.
- 본인 관리 프로필: 이름/닉네임, 소개, 프로필 이미지(권한 확인), 카테고리·해시태그, 영상 포트폴리오 링크, 제작 방식, 관심 광고 카테고리, 희망 협업 단가, 가능 일정, 응답 가능 여부, 연락 방식.
- `contact_email`/`contact_phone`은 본인 직접 입력, 인증/검증·공개 동의. 공개 범위 `hidden`, `after_accept`, `verified_brands`, `public` 중 선택. 기본 `hidden`.
- 등록된 통계: API 원문 데이터와 시점 표시; 파생 통계는 정책 승인·데이터 출처 조건에 맞게 표시.
- 공고 목록, 지원조건 필터, 잔여 지원권, 지원 제출, 지원 현황/취소 가능 정책, 기업과 채팅, 메시지 차단/신고.
- 스폰서 상품 구매, 슬롯 점유율·잔여 기간·광고 표시·종료·연장.
- 자동분석 태그 수정 제안, 본인 확인 정보 정정/삭제, 공개 정보 수정 요청.

### 관리자

## 4. 검색 랭킹과 광고 경계
- 검색 시스템은 **검색 조건 필터**(hard filter) → **콘텐츠 매칭**(태그·임베딩) → **설명 가능한 organic 추천 점수** → 사용자가 검토하는 후보 추천 순서로 동작.
- 외부 YouTube API 파생 점수/평균/태그는 별도 정책 승인 없으면 `pending_approval` 플래그로 제외한다. 단순 raw subscriber count 기반 필터는 정책 및 데이터 정확도 확인 후 제공.
- 유료 스폰서는 쿼리에 부합하는 유튜버만 **독립적인 '스폰서' 카드/캐러셀**에 표시한다. `is_sponsored`로 광고 라벨을 강제하고 organic score를 변경하지 않음. 예: 검색결과 페이지 상단 최대 2명, 초과 시 만료/예산/순환배치; 비노출 사유는 관리자에게 보임.
- 추천 근거: 공통 태그, 콘텐츠 분야, 예상 제작 형태, 협업 가능 여부, 정보 출처/시점. 없는 오디언스 인구통계·ROI를 상상해 쓰지 않음.

## 5. 최근 평균 조회수 상세 정의 (조건부 출시)
UI 필터는 `최근 30일 업로드 영상`, `최근 90일 업로드 영상`, `최근 10개 업로드 영상`, `최근 20개 업로드 영상` 중 선택 가능하되 **YouTube 파생 지표 정책 승인이 확인되기 전 실제 API 파생 필터는 비활성**.
정의(승인 또는 독립·동의 데이터에 한정):
- 선택한 기간 내 **공개 상태**의 일반 업로드 중 API로 실제 `viewCount`를 확인할 수 있는 영상만 포함.
- Shorts / live / 일반 영상을 구분할 수 있는 신뢰 가능한 출처·판정 근거가 없으면 전체 영상 기준이라고 표시; 임의로 Shorts를 확정 분류하지 않음.
- 산술평균 `sum(viewCount)/count`; count=0이면 null(0이 아님). 반올림 기준/표본 수/수집 기준 날짜/변동 가능성 표기.
- 별도로 중앙값·최근 영상 목록, 조회수 편차를 비교해 선택 편향 경고(선택적 P1).
- channel viewCount는 누적 채널 전체 조회수이므로 **최근 평균 영상 조회수의 대체값으로 사용 금지**.
- YouTube가 제공하지 않는 '실제 광고 성과/전환율/성별 시청자 비율' 등을 생성하지 않음.

## 6. 상태 기계
- job: `draft → awaiting_entitlement → published → paused/closed/expired/removed`; published 재차 요청 idempotent.
- application: `draft → awaiting_entitlement → submitted → shortlisted → accepted/rejected/withdrawn → in_progress → completed/disputed`; 유효 transition 역할 검증.
- conversation: `open → archived/blocked`; 참여자/관리자 중재 범위 한정.
- payment: `created → checkout_pending → confirming → approved | failed | cancelled | refunded`; 승인 응답과 자체 권한 발급 구분.
- creator_claim: `unclaimed → pending → verified/rejected/revoked`; 공개 디렉터리와 가입회원 분리.
- sync job: `queued → leased → running → succeeded/failed/retry/dead_letter`; idempotency uniqueness.

## 7. 필수 화면·행동별 예외
- 미로그인, 권한 부족, 미인증 채널, 비공개 연락처, 토스 결제 취소/중복 승인, API 할당량 소진, AI 서버 중단, 평균 조회수 이용 승인 대기, 신고/정지 계정 모두 상세한 UX 처리 필요.
- 채팅 상대가 차단/탈퇴/휴면이면 메시지 제한·기존 데이터 처리 원칙 적용.

## 8. KPI (실측과 가정 구분)
- 브랜드 검색 유료 시도→승인→첫 후보 도달 전환율, 공고 작성→게시 전환, 지원/공고 비율, 채팅 시작율, 후보 비교/제안 전환, 크리에이터 인증율, 일일 채널 동기화 성공률, AI 태그 승인률, 지원권 사용률, 테스트 결제 오류율.
- 실제 광고 성사 수수료/성과 ROI는 양측 확인 또는 별도 추적 체계 전에는 사실로 주장하지 않는다.
