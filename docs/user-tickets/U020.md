# U020 — 공개 베타 출시·사고 연락·운영 책임

담당: 사용자 · 우선순위: P0 · 현재 상태: NO_GO · 기준일: 2026-11-19

이 문서는 외부 작업의 실행 명세다. 문서 작성만으로 설정/승인/배포가 완료된 것은 아니다. 이전에 설정한 항목은 현재 상태를 확인해 증거를 남기면 재작업하지 않아도 된다.

## 목적·완료 조건

정책/실제 데이터/보안/복구 증빙을 확인한 뒤 사용자 본인이 출시를 결정하고 지속 운영 담당·지원 시간을 정한다.

## 시작 전에 개발자가 준비할 것

D088 실제 배포 URL 검증 보고·모든 P0 결과·U001~U019 중 해당 출시 게이트 결과·알려진 제한·복구/지원 절차.

## 사용자가 수행할 순서

1. 릴리스 commit·URL·배포 환경이 D088 증거와 동일한지 확인한다. 검증 뒤 다른 commit이 배포됐으면 재검증을 요청한다.
2. 필수 P0 중 실패/미검증·실제 데이터 허가 미확정·외부 가입 실패·삭제/권한 문제·백업 부재가 없는지 확인한다. 단순 테스트 수량만 보지 않는다.
3. P1/P2 선택 기능은 미활성 상태와 사용자 안내를 확인한다. Instagram/TikTok/LLM/Toss TEST가 선택 범위이면 베타 필수 조건으로 무조건 묶지 않는다.
4. 무료/비상업 호스팅 조건·개인정보 정책·지원 연락·신고/삭제 운영 책임·장애 대응자가 실제 운영 가능한지 확인한다.
5. GO/NO-GO 결정·시각·승인자·허용 사용자 범위·알려진 제한을 기록한다. 출시 조작은 사용자가 수행하고 개발자는 승인된 주소를 재확인한다.
6. 초기 관측 시간·일상 점검·권리 요청 처리·quota/비용 점검 주기를 정하고 장애 시 기능 중단/배포 복구/DB forward fix 담당을 정한다.

## 검증·개발자 인계

서명 대신 사용할 승인 기록·검증 commit/URL·GO/NO-GO·남은 제한·모니터/지원/복구 담당·초기 점검 결과.

위 정보를 해당 개발 티켓 담당에게 전달한다. 성공 여부는 계정 화면의 설정과 실제 기능 검증을 함께 확인한다. 비밀값은 전달하지 않는다.

## 실패·중단·복구

출시 게이트 실패는 NO-GO다. 일정이나 외형 완성도를 이유로 실패를 승인 처리하지 않는다. 필요하면 작은 비공개 파일럿으로 범위를 줄인다.
