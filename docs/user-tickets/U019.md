# U019 — 실제 테스트 참여·브라우저 승인

담당: 사용자 · 우선순위: P0 · 현재 상태: PARTIAL_VERIFIED · 기준일: 2026-11-19

이 문서는 외부 작업의 실행 명세다. 문서 작성만으로 설정/승인/배포가 완료된 것은 아니다. 이전에 설정한 항목은 현재 상태를 확인해 증거를 남기면 재작업하지 않아도 된다.

## 목적·완료 조건

OAuth·이메일 링크·2FA·TEST 결제 인증 등 사용자만 가능한 화면을 수행하고 테스트 결과를 확인한다.

## 시작 전에 개발자가 준비할 것

D009/D010/D022/D023/D066/D084의 시나리오별 URL·계정 역할·기대 결과·실패 대응. 실제 인증은 사용자만 수행한다.

## 사용자가 수행할 순서

1. 배포 URL·commit·환경·TEST 표시·테스트 계정을 확인한다. 실제 개인 데이터 사용을 최소화한다.
2. 이메일 가입 링크·비밀번호 재설정·MFA 등 본인 인증 화면을 직접 완료한다. 인증 코드/쿠키/비밀번호를 에이전트에 붙여 넣지 않는다.
3. 승인된 SNS 연결은 필요한 scope를 읽고 동의하며 연결 후 철회도 테스트한다. 불필요한 권한이면 중단한다.
4. Toss는 TEST 고지를 확인한 뒤 본인만 가능한 인증을 완료한다. 성공/실패/취소 각각의 결과 화면과 서버 검증 결과를 개발자와 대조한다. 실제 금전 거래는 하지 않는다.
5. 브랜드→캠페인→추천→후보 비교→실제 광고 이력→동의한 크리에이터 제안→다른 역할 로그인→수락→대시보드 갱신을 수행한다.
6. 모바일·새로고침·재로그인·권한 거부를 확인하고 최소한의 마스킹된 결과만 남긴다.

## 검증·개발자 인계

시나리오·URL/commit·수행 시각·역할·기대/실제 결과·실패 지점. 인증 URL token/query·개인 결제 정보 제외.

위 정보를 해당 개발 티켓 담당에게 전달한다. 성공 여부는 계정 화면의 설정과 실제 기능 검증을 함께 확인한다. 비밀값은 전달하지 않는다.

## 실패·중단·복구

인증/동의가 막히면 해당 시나리오만 차단하고 세션 공유나 보안 비활성화로 우회하지 않는다.
