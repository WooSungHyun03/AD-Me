# U008 — Auth 외부 콘솔 설정

담당: 사용자 · 우선순위: P0 · 현재 상태: PARTIAL_VERIFIED · 기준일: 2026-11-19

이 문서는 외부 작업의 실행 명세다. 문서 작성만으로 설정/승인/배포가 완료된 것은 아니다. 이전에 설정한 항목은 현재 상태를 확인해 증거를 남기면 재작업하지 않아도 된다.

## 목적·완료 조건

사이트 URL·허용 콜백·메일 템플릿·세션/MFA/비밀번호 보호 설정을 환경별로 적용한다.

## 시작 전에 개발자가 준비할 것

D009/D010/D013/D016가 실제 구현한 callback/recovery 경로·메일 템플릿 방식·관리자 MFA 요구 목록. 현재 /auth/callback 및 /auth/confirm이 구현·배포되었다. 관리자 MFA 등 남은 범위는 아래 실행 기록을 확인한다.

## 사용자가 수행할 순서

1. Supabase Authentication의 URL Configuration에서 환경별 Site URL을 확인된 HTTPS 앱 origin으로 설정한다.
2. Redirect allowlist에는 개발자가 구현한 정확한 callback/recovery URL을 등록한다. 개발용 localhost는 개발 환경에만 사용하고 운영에 불필요한 광범위 wildcard를 넣지 않는다.
3. 메일 템플릿의 ConfirmationURL/token_hash/code 교환 방식이 구현된 서버 라우트와 일치하는지 D009 검토 자료대로 설정한다. 존재하지 않는 /auth/callback을 등록했다고 완료 처리하지 않는다.
4. 이메일 확인·비밀번호 기준·재발송 제한·세션 설정을 D013 요구와 맞춘다. 현재 플랜의 leaked-password 보호/MFA 지원 범위를 확인하고 사용할 수 없는 기능을 켰다고 기록하지 않는다.
5. 관리자 권한 provision은 개발자가 준 최소 대상 변경만 적용하고 MFA 등록은 관리자가 직접 수행한다. 복구 코드는 비공개 보관한다.
6. 외부 도메인 redirect 거부·만료 링크·recovery 계정 혼동·MFA 없는 관리자 접근을 개발자와 검증한다.

## 검증·개발자 인계

origin/허용 경로·템플릿 방식/버전·지원 보안 설정·재설정/관리자 MFA 검증 결과. 토큰 URL 원문 제외.

위 정보를 해당 개발 티켓 담당에게 전달한다. 성공 여부는 계정 화면의 설정과 실제 기능 검증을 함께 확인한다. 비밀값은 전달하지 않는다.

## 실패·중단·복구

로그인 loop는 쿠키 origin·Site URL·allowlist·콜백 구현·템플릿을 함께 대조한다. 허용 URL을 모든 도메인으로 넓혀 해결하지 않는다.
