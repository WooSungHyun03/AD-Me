# U005 — Vercel 프로젝트·Git 연결·배포 실행

담당: 사용자 · 우선순위: P0 · 현재 상태: USER_ACTION_REQUIRED · 기준일: 2026-11-19

이 문서는 외부 작업의 실행 명세다. 문서 작성만으로 설정/승인/배포가 완료된 것은 아니다. 이전에 설정한 항목은 현재 상태를 확인해 증거를 남기면 재작업하지 않아도 된다.

## 목적·완료 조건

배포 사이트의 프로젝트 설정·프로덕션/프리뷰·Git 연결·배포/재배포·승격/롤백을 직접 수행한다.

## 시작 전에 개발자가 준비할 것

D085 release packet·검증된 commit·Vercel 설정·U004 DB 적용 여부·U006 설정명 목록. 기존 ad-me 프로젝트를 재사용할지 확인한다.

## 사용자가 수행할 순서

1. Vercel에서 ad-me 프로젝트·계정/팀·연결 저장소·기본 브랜치를 확인한다. 기존 별칭은 https://ad-me-topaz.vercel.app 이다.
2. Settings에서 Framework=Next.js, package.json이 위치한 Root Directory, Node 22 호환성, npm ci/install 및 npm run build를 확인한다. UI 표시와 vercel.json 설정을 일치시킨다.
3. Production/Preview가 사용할 Supabase 프로젝트와 APP_URL을 U006 표와 대조한다. preview가 운영 DB를 무심코 쓰지 않게 한다.
4. Vercel Hobby 사용 가능성을 서비스 용도와 대조한다. 무료 베타여도 B2B 마케팅 서비스가 개인 비상업 용도인지 자동 단정할 수 없다. 지원 문의/적합 플랜 판단 전 무료 운영을 보장하지 않는다.
5. 사용자가 승인한 commit을 선택해 검증용 배포를 실행한다. 공개 전 검증이 가능한 배포 방식/보호 설정은 현재 플랜에서 확인한다. 지원되지 않으면 보호되는 별도 검증 환경을 선택한다.
6. 배포 로그에서 READY·commit·환경·URL을 기록한다. 200 화면만으로 앱 정상이라 판단하지 말고 D088 검증을 요청한다. 검증된 결과로 U020 출시 판단을 한다.
7. 환경변수 변경 후에는 새 배포가 필요하다. 실패 시 이전 검증된 배포를 UI에서 선택해 복구하고 DB 호환성도 확인한다.

## 검증·개발자 인계

배포 ID·정확한 URL·commit·환경·READY 상태·빌드 결과·선정한 플랜 적합성 판단·롤백 대상.

위 정보를 해당 개발 티켓 담당에게 전달한다. 성공 여부는 계정 화면의 설정과 실제 기능 검증을 함께 확인한다. 비밀값은 전달하지 않는다.

## 실패·중단·복구

404는 프레임워크/루트·401/403은 protection·빌드 오류는 환경/버전을 확인한다. 보호를 무조건 끄거나 오류 로그에 키를 출력하지 않는다.
