# U009 — YouTube 프로젝트·API 키 발급/등록

담당: 사용자 · 우선순위: P0 · 현재 상태: USER_ACTION_REQUIRED · 기준일: 2026-11-19

이 문서는 외부 작업의 실행 명세다. 문서 작성만으로 설정/승인/배포가 완료된 것은 아니다. 이전에 설정한 항목은 현재 상태를 확인해 증거를 남기면 재작업하지 않아도 된다.

## 목적·완료 조건

Google 프로젝트·API 활성화·키 제한·무료 쿼터 확인·서버 키 등록을 수행한다.

## 시작 전에 개발자가 준비할 것

D017/D019가 요구하는 YouTube Data API 필드·서버 호출 방식·환경변수명·정책/쿼터 예상·허용 seed 채널 목록.

## 사용자가 수행할 순서

1. Google Cloud Console에서 AD Me 전용 프로젝트를 선택/생성하고 YouTube Data API를 활성화한다. 다른 서비스의 공유 프로젝트/키를 재사용하지 않는다.
2. Credentials에서 서버용 API 키를 발급하고 API restriction을 YouTube Data API로 제한한다. 키는 브라우저에 전달하지 않는다.
3. 애플리케이션 제한은 실제 서버 실행 환경과 호환되는 방식으로 설정한다. 고정 egress IP가 없는 서버에 임의 IP 제한을 넣거나 브라우저 referrer 제한으로 서버 보안이 된다고 가정하지 않는다.
4. 쿼터/사용량 화면에서 현재 할당량과 한도를 확인한다. 결제 계정/유료 리소스 연결은 필요성과 사용자 비용 결정을 별도로 확인한다.
5. D003/D019가 확정한 서버 환경변수명으로 Vercel의 해당 환경에 직접 등록하고 재배포한다. 현재 코드에는 수집 어댑터가 없으므로 등록만으로 수집 완료가 아니다.
6. 허용된 실제 채널 1개로 개발자의 요청 결과·쿼터 소모·수집시각·반환 필드를 검증한다. 이름 검색 대량 호출 대신 seed 기반 시작을 권장한다.

## 검증·개발자 인계

프로젝트 식별자·API 활성화·API 제한 종류·할당량·환경·실제 샘플 수집 결과. 키 값 제외.

위 정보를 해당 개발 티켓 담당에게 전달한다. 성공 여부는 계정 화면의 설정과 실제 기능 검증을 함께 확인한다. 비밀값은 전달하지 않는다.

## 실패·중단·복구

403/429는 API 활성·키 restriction·쿼터·정책을 구분한다. 다른 키 순환/여러 프로젝트로 제한을 우회하지 않는다.
