# U018 — 관측·알림·백업 외부 계정 설정

담당: 사용자 · 우선순위: P0 · 현재 상태: PARTIAL_VERIFIED · 기준일: 2026-11-19

이 문서는 외부 작업의 실행 명세다. 문서 작성만으로 설정/승인/배포가 완료된 것은 아니다. 이전에 설정한 항목은 현재 상태를 확인해 증거를 남기면 재작업하지 않아도 된다.

## 목적·완료 조건

무료 플랜 한도·수신 채널·외부 토큰·백업 위치·접근 권한을 설정한다. 유료 전환은 별도 판단한다.

## 시작 전에 개발자가 준비할 것

D086/D087 관측·alert·백업 산출물과 무료 범위·보관처·복구 테스트 요구. 사용할 공급자를 먼저 확정한다.

## 사용자가 수행할 순서

1. 기존 Vercel/Supabase 관측 기능과 한도를 확인하고 추가 계정이 꼭 필요한지 결정한다. 필요한 경우 지원 조건·무료 한도·데이터 보존을 확인한다.
2. 오류·API 쿼터·DB/Storage/트래픽·메일 발송·LLM 비용 알림의 수신자와 대응 시간을 정한다. 개인정보가 포함된 알림 본문은 금지한다.
3. 추가 공급자 키/토큰·webhook을 최소 권한으로 발급해 지정된 서버/알림 저장소에 직접 등록한다. URL 자체가 secret이면 문서에 넣지 않는다.
4. 백업 위치·암호화·접근권한·보존/삭제 규칙을 정한다. 무료 플랜의 backup/PITR 가능 범위를 확인하고 제공되지 않는 기능은 준비됐다고 기록하지 않는다.
5. 개발자가 만든 안전한 백업 산출물/실행기를 사용자 승인 방식으로 설정한다. Auth/Storage 파일 포함 여부·누락 범위를 확인한다.
6. 모의 장애 알림을 실제 수신하고 격리 복원 결과·RPO/RTO를 검토한다. 운영 DB에 시험 복원을 하지 않는다.

## 검증·개발자 인계

선정 도구/플랜·알림 수신 확인·보관처 유형(비밀 경로 제외)·백업 범위·복원 측정·한도 경고.

위 정보를 해당 개발 티켓 담당에게 전달한다. 성공 여부는 계정 화면의 설정과 실제 기능 검증을 함께 확인한다. 비밀값은 전달하지 않는다.

## 실패·중단·복구

무료 범위에서 복구 요구를 충족하지 못하면 출시 기준을 조정하거나 사용자 비용 판단을 기다린다. 데이터가 있으니 백업도 있다고 가정하지 않는다.
