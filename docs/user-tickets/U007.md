# U007 — SMTP 계정·키·발신 도메인 설정

담당: 사용자 · 우선순위: P0 · 현재 상태: USER_ACTION_REQUIRED · 기준일: 2026-11-19

이 문서는 외부 작업의 실행 명세다. 문서 작성만으로 설정/승인/배포가 완료된 것은 아니다. 이전에 설정한 항목은 현재 상태를 확인해 증거를 남기면 재작업하지 않아도 된다.

## 목적·완료 조건

메일 공급자 가입·키 발급/등록·발신자 인증·SPF/DKIM/DMARC·Supabase SMTP 연결을 직접 수행한다.

## 시작 전에 개발자가 준비할 것

D009 인증 링크/템플릿 계약·선정 후보 SMTP 지원·한도·발신 도메인 요건. 메일 공급자는 아직 특정하지 않았다.

## 사용자가 수행할 순서

1. SMTP 지원·현재 무료 한도·실수신자 제한·발신 도메인 인증·이용 목적 적합성을 확인한 뒤 공급자를 선택하고 계정을 만든다. 도메인/유료 비용이 필요하면 선택을 별도로 결정한다.
2. 공급자가 제시한 DNS 레코드를 도메인 관리 화면에 정확히 등록한다. SPF를 무작정 두 개 만들지 말고 기존 발신자와 합쳐 검토한다. DKIM/DMARC 검증 상태를 확인한다.
3. 공급자에서 SMTP host/port/username/password와 허용 발신자 정보를 확인한다. API key와 SMTP password가 같은지 공급자 문서로 확인한다.
4. Supabase Authentication의 이메일/SMTP 설정에 해당 값을 직접 입력한다. 확인된 포트·암호화 조건을 사용하고 SMTP 비밀값을 Vercel 공개 환경변수에 넣지 않는다.
5. Supabase 기본 발신 제한을 SMTP 설정으로 해결하되 이메일 확인 기능을 꺼서 우회하지 않는다. 발송 한도와 재발송 cooldown을 설정한다.
6. 팀 밖 실제 이메일로 가입·인증·재설정·만료/재발송·스팸함을 검증한다. 메일 보안 스캐너의 링크 사전 방문 문제도 D009 담당과 확인한다.

## 검증·개발자 인계

공급자/발신자 인증 상태·설정 완료 시각·메일 유형별 실제 수신/링크 결과·마스킹된 발송 ID·한도.

위 정보를 해당 개발 티켓 담당에게 전달한다. 성공 여부는 계정 화면의 설정과 실제 기능 검증을 함께 확인한다. 비밀값은 전달하지 않는다.

## 실패·중단·복구

인증 링크 실패는 SMTP 수신 문제와 앱 callback 문제를 나눠 전달한다. 무료 발신 제한 때문에 불가능하면 외부 가입을 차단 상태로 유지한다.
