# U006 — 환경변수·시크릿 등록과 교체

담당: 사용자 · 우선순위: P0 · 현재 상태: PARTIAL_VERIFIED · 기준일: 2026-11-19

이 문서는 외부 작업의 실행 명세다. 문서 작성만으로 설정/승인/배포가 완료된 것은 아니다. 이전에 설정한 항목은 현재 상태를 확인해 증거를 남기면 재작업하지 않아도 된다.

## 목적·완료 조건

개발자 제공 변수명 목록에 따라 Supabase/Vercel/CI에 키를 직접 등록한다. 값은 채팅·티켓에 올리지 않는다.

## 시작 전에 개발자가 준비할 것

docs/handoff/ENVIRONMENT_CONTRACT.md와 D003가 확정한 설정명·저장 위치·현재/예정 구분. 비밀값 자체는 개발자 문서에 포함하지 않는다.

## 사용자가 수행할 순서

1. 환경마다 대상 Vercel 프로젝트/Environment와 Supabase ref를 확인한다. 이름이 같은 TEST/운영 키를 혼합하지 않는다.
2. 아래 환경 계약의 현재 사용 변수만 해당 콘솔에서 등록한다. Vercel: Project Settings의 Environment Variables; Supabase: Edge Functions의 Secrets. 메뉴 명칭이 바뀌면 기능명으로 찾는다.
3. NEXT_PUBLIC_SUPABASE_ANON_KEY는 현재 코드가 읽는 정확한 이름이다. 다른 종류의 키로 전환하려면 D003 코드 변경과 함께 수행한다. secret/service-role은 NEXT_PUBLIC_로 등록하지 않는다.
4. TOSS_SECRET_KEY는 payment-confirm Edge Function secret에만 등록한다. Vercel에는 서버 시크릿을 중복 배포하지 않는다. built-in Supabase function credentials는 임의 덮어쓰지 않는다.
5. 새 YouTube/LLM/Meta/TikTok 변수는 해당 코드와 설정 계약이 구현·확정된 뒤 등록한다. 예정 이름을 넣었다고 기능이 동작하는 것은 아니다.
6. 값을 화면 캡처·티켓·GitHub·채팅으로 공유하지 않고 등록한 이름/환경/시각만 전달한다. 변경 후 사용자가 필요한 재배포를 실행한다.
7. 노출 의심 시 공급자에서 폐기/재발급하고 새 값 등록·배포·검증 후 이전 키를 정리한다. 토큰 일부도 증거에 붙이지 않는다.

## 검증·개발자 인계

변수명·저장 위치·환경·등록/교체 시각·재배포 ID·개발자의 연결 확인. 값/인증 헤더/키 일부는 제외.

위 정보를 해당 개발 티켓 담당에게 전달한다. 성공 여부는 계정 화면의 설정과 실제 기능 검증을 함께 확인한다. 비밀값은 전달하지 않는다.

## 실패·중단·복구

missing env는 이름·scope·재배포 여부부터 확인한다. 키를 브라우저 번들에 넣거나 공개 health로 값을 노출해 진단하지 않는다.
