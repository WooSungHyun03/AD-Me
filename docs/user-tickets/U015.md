# U015 — Toss TEST 계정·호환 키·등록

담당: 사용자 · 우선순위: P1 · 현재 상태: PARTIAL_VERIFIED · 기준일: 2026-11-19

이 문서는 외부 작업의 실행 명세다. 문서 작성만으로 설정/승인/배포가 완료된 것은 아니다. 이전에 설정한 항목은 현재 상태를 확인해 증거를 남기면 재작업하지 않아도 된다.

## 목적·완료 조건

사용 가능한 TEST 상점/문서 체험 키 범위와 SDK v2 호환성을 확인하고 클라이언트·서버 TEST 키를 직접 등록한다. 라이브 키는 제외한다.

## 시작 전에 개발자가 준비할 것

D065/D066의 TEST 격리·선택한 Toss 결제 제품·SDK v2 호환 키 종류·승인 경로와 주문 테스트 시나리오.

## 사용자가 수행할 순서

1. Toss 개발자센터에 로그인하고 TEST 모드/상점 또는 개발 연동 체험 범위를 확인한다. 사업자 미등록 상태에서 모든 키/수단이 제공된다고 가정하지 않는다.
2. 선택한 SDK v2 결제 제품의 공식 문서에서 필요한 키 종류를 개발자와 대조한다. v2 SDK 버전과 상점의 결제 제품 종류는 다른 개념이다.
3. 같은 세트의 TEST client/secret만 선택한다. 라이브 키는 사용하지 않는다. 사용할 수 없는 제품은 문서 체험 지원 범위로 축소하거나 차단 기록을 남긴다.
4. NEXT_PUBLIC_TOSS_CLIENT_KEY는 격리 TEST Vercel 환경에, TOSS_SECRET_KEY는 해당 Supabase Edge Functions Secrets에 직접 등록한다. 운영 무료 환경과 섞지 않는다.
5. 사용자가 TEST 앱을 재배포하고 U019에서 성공·실패·취소를 수행한다. 개발자가 서버 승인·금액/소유권·중복·이용권 활성화/만료와 실제 거래 내역을 대조한다.
6. 실제 provider 테스트를 완료하지 못하면 TEST 연동 코드는 있음/공급자 검증 미완료로 기록한다.

## 검증·개발자 인계

상점 TEST 확인·제품/키 종류(값 제외)·배포 ID·마스킹한 TEST 주문/거래 ID·성공/실패/취소 및 중복 승인 결과.

위 정보를 해당 개발 티켓 담당에게 전달한다. 성공 여부는 계정 화면의 설정과 실제 기능 검증을 함께 확인한다. 비밀값은 전달하지 않는다.

## 실패·중단·복구

INVALID_API_KEY는 세트·환경·제품 호환을 확인한다. 가짜 결제 성공·수동 paid DB 수정·라이브 키 전환으로 해결하지 않는다.
