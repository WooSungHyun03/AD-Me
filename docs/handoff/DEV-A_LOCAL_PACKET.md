## 검토 후 외부 콘솔 적용 순서

1. **U003/U005 격리 확인.** 무료 베타와 TEST 프로젝트가 분리됐는지 확인한다. 이 패킷은 SQL 마이그레이션을 포함하지 않는다. 기존 `create_test_order` RPC는 D001 이전 Supabase에서 직접 호출 가능하므로, TEST 설정은 격리 프로젝트에서만 적용한다.
2. **U006/U008 환경 및 인증.** 각 환경의 Vercel 앱 origin과 해당 Supabase Site URL을 동일하게 설정한다. exact `/auth/confirm` 리다이렉트와 기존 `confirmation.html`·`recovery.html` 토큰 해시 템플릿을 확인한다. 가입 확인을 켠 상태에서만 앱 발송 플래그를 활성화한다.
3. **U015 TEST 환경.** 승인된 TEST 프로젝트의 Vercel과 Edge Function에 동일한 모드와 결제 플래그를 적용한다. 승인 기능에는 기존 TEST 전용 키만 사용한다. 환경 이름·위치는 [환경 계약](ENVIRONMENT_CONTRACT.md)에 정리했다.
4. **D085/U019 적용과 검증.** 리뷰한 소스로 인증, RLS, TEST 카탈로그/금액·중복·실패 계약을 격리 환경에서 확인한다. 사용자에게 필요한 작업은 콘솔 승인과 배포다. 코드 병합·검증을 개발 담당이 준비한다.

결제 경로를 닫아야 할 때는 Vercel과 Edge의 TEST 결제 플래그를 둘 다 끈다. 가입·재발송·복구 요청은 앱 메일 플래그를 끄면 중단된다. 인증 템플릿이나 앱 버전을 되돌릴 때는 확인 링크의 경로와 증표 방식이 맞는지 함께 확인한다.

## DEV-B 변경 계약

- D001/D048은 `src/lib/config.ts`의 `getConfig()`와 기능 상태를 사용한다. 수집·LLM에서 실제 어댑터를 연결하기 전까지 미가용 상태를 유지한다.
- API 오류는 `error.message`와 `error.code`, `error.requestId`, 헤더 `X-Request-Id`를 제공한다. 비즈니스 거절과 공급자 장애를 분리한다. [API 계약](../API_CONTRACTS.md)
- D017/D019/D026/D033은 크리에이터·관측·공개 DTO 초안을 검토한다. 데이터 승인/보존과 RLS는 API 표시보다 먼저 확인한다. `src/lib/ingestion/creator-contract.ts`
- D012/D044는 캠페인 브리프 기간과 금액·산출물 계약을 검토한다. 기존 v1 엔드포인트와 데이터의 호환을 유지해야 한다. `src/lib/campaign-brief.ts`
