# D062 — 차단·신고 누적·스팸·사칭 검토·연락 제한 (2026-11-22)

상태: 구현·**격리 로컬 Supabase 검증 완료**(`db reset`으로 0001~0014 적용) / 운영 DB 미적용(마이그레이션 0014).

## 단일 권한 helper
- `contact_denied(sender, recipient)`가 연락 가능 여부를 정한다. 반환값은 null(허용) / `blocked` / `contact_restricted`.
  - 내부 전용이다(authenticated 실행 권한 없음). 남의 관계를 조회할 수 없다.
- 이 helper를 쓰는 곳:
  - 새 제안·지원과 메시지: `guard_contact` 트리거(invoker. 브라우저 요청만 판별) → `contact_check`(definer, 발신자는 항상 `auth.uid()`).
  - 수락: `transition_proposal`. 요청 뒤에 차단되면 수락은 거부하고 거절·취소는 허용한다.
  - 알림: `notify_proposal_event`. 차단 관계에서는 알림을 만들지 않는다. 메시지는 이미 트리거에서 막힌다.
- 오류 문구는 "이 상대와는 더 이상 연락할 수 없습니다"로 누가 차단했는지와 관계없이 같다. 차단 사실이 상대에게 드러나지 않는다.

## 차단
- `block_counterparty(proposal)`: 공유 협업에서만 차단할 수 있다(사용자 id 열거 불가).
  - 둘 사이의 응답 대기 요청을 닫는다. 내가 보낸 것은 취소, 받은 것은 거절이며, 상대에게 알림은 가지 않는다.
- `unblock_user`는 차단한 본인만, `my_blocks`는 본인 목록만. `user_blocks`는 차단한 사람만 조회할 수 있고 직접 쓰기는 회수했다.
- UI:
  - 협업 카드의 "상대 차단"은 화면 안에서 2단계로 확인한다(브라우저 대화상자 없음). 차단 후 메시지 폼이 사라진다.
  - 설정의 "차단한 상대"에서 해제할 수 있다.

## 스팸·다계정 속도 제한
- 메시지: 발신자 10분 30건, 수신자 10분 60건(모든 발신자 합산).
- 제안·지원:
  - 발신자 24시간 20건.
  - 크리에이터가 받는 브랜드 제안은 1시간 10건(여러 계정을 합산하므로 다계정 공세를 막는다).
  - 브랜드 캠페인에 들어오는 지원은 시간당 상한을 두지 않았다(인기 캠페인 정상 흐름. 첫 회귀에서 공용 브랜드가 막혀 수정함).
- 서버 경로(definer·seed)는 제한하지 않는다.

## 신고 누적·사칭 검토·연락 제한
- 신고 유형에 `impersonation`(사칭 신고)을 추가했다. 출처가 필수이고 운영자가 직접 검토하며, D058 재심 경로를 그대로 쓴다.
- **자동 제재 없음**:
  - 신고가 쌓여도 제한·비공개가 자동으로 걸리지 않는다.
  - 관리자 큐에 "신고 누적 N명(30일, 검토 신호)"만 표시한다(서로 다른 요청자 기준).
- `restrict_contact(report, days, reason)`(관리자만):
  - 1~30일 **기한부**(DB check 제약으로 영구 불가).
  - 계정이 있는 프로필에만 적용한다. 수집 프로필은 `no_account`이므로 비공개 처리를 안내한다.
  - 관리자 화면에서는 검토 시작 또는 처리 완료 상태의 신고·사칭 건에만 제한 버튼이 보인다.
- 제한된 사용자:
  - 새 제안·지원·메시지를 보낼 수 없다.
  - 대시보드에 사유·해제 예정일 안내와 이의신청 폼이 있다(1회, 본인만).
  - 기한이 지나면 자동으로 풀린다.
- `lift_restriction`(관리자). 제한·해제는 모두 `audit_log`에 남는다.
