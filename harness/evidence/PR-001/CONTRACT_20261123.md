# PR-001 product-condition extraction contract (not a completed product flow)

Prepared the independent local-model adapter and shared-vocabulary/Zod consumer contract before an authenticated queue/consumer is connected. scripts/product_conditions.py accepts bounded name/description/explicit audience text, minimizes contact fields, fingerprints the minimized source, sends one escaped untrusted JSON block through the bounded local transport and validates model/version/usage. Only the shared current YouTube topic, initial vibe and format vocabulary is allowed. Every suggestion must copy a value inside an exact quote in its named source field; invented evidence is omitted, duplicates removed and unsupported demographics/budget/efficacy/candidate inference rejected. Outputs are unbound-product-text-v1, require confirmation and remain applied=false. No search, credit use, account lookup, job enqueue, publication or message send is performed by the helper.

The Zod consumer independently checks schema, expected server fingerprint, evidence, duplicate conditions and mandatory confirmation. A caller/model cannot supply a trusted owner ID. Ownership is intentionally not represented as verified: the future authenticated producer must fetch its own RLS-protected brand product and bind its version before accepting output. Current manual recommendation UI remains unchanged and usable if this helper/model fails.

Four provider-free Python tests cover5 Korean fictional product examples and source/evidence/version/privacy/bad input/timeout cases. Three TS contracts cover shared topic compatibility, valid unapplied proposals and source/extra-field/duplicate/inference/confirmation failures. They use synthetic model responses, not actual model inference or account authorization. Existing source/product RLS was not weakened.
