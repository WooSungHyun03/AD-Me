# D037 · 2026-11-25 opt-in in-app new-candidate alerts (new; earlier evidence unchanged)

Base: origin/main `36e57e9`. Scope: loopback replica `d002-replica` only. No hosted DB, deployment, email or provider call.

## Reproduction (before) — `d037_before` query on the replica
- `adme_search.saved_conditions` had no notify column (0), no scheduled job (0), and `notifications.kind` allowed only `status|message|deliverable`: a brand's saved search could never produce an alert. UI said "신규 후보 알림은 아직 제공하지 않습니다."

## Change
- Migration `20261125150000_d037_saved_search_alerts.sql` (expand/switch, manifest + pending packet row #22):
  - `saved_conditions.notify` (default **off**) + `baseline_revision`; private `adme_search.seen_candidates(condition, creator)` PK = one alert per creator per condition.
  - `adme_search.scan_condition/scan_alerts` (pg_cron `adme-saved-search-alerts`, every 15 min): runs the existing catalog matcher `adme_creator.filtered_page` **as the owner** (owner visibility, owner catalog quota; quota overrun skips to next tick). Opt-in or filter change re-baselines silently; job-level advisory lock; row `for update skip locked` vs concurrent edits; inactive accounts skipped.
  - `saved_search_alerts(id, expected, notify)`: owner-only, revision CAS, quota. `saved_search_list` adds `notify`.
  - **DEV-B D052 shared expand**: `notifications.proposal_id` nullable, `saved_search_id` (cascade on delete), `new_count`, kind `saved_search`, subject check keeps proposal rows exactly as before; read policy adds own `saved_search` rows (active account). **D015 service-email trigger now skips `saved_search`** (email waits for D053).
- API `PATCH /api/saved-searches` (strict `savedSearchAlerts`; `savedSearchInput` still rejects alert fields). UI checkbox "새 후보 알림" (state flips only after server confirmation), honest copy. Inbox text "저장 검색 조건에 새로 맞는 크리에이터 N명이 있습니다" → `/saved-searches`; dashboard per-proposal markers ignore it.
- D084 helper fix: `dropCreatorProfile` also removes proposals created during the spec when restoring a prior row (10 leaked pending proposals found and removed on the replica).
